## Gaps between the references and the design reference

1. The design reference regenerates the token from a bare button. Every token screen above puts a confirmation or at least a consequence statement in front of that act, because regeneration breaks every client holding the old token. The screen needs a confirmation step the design reference omits.
2. The design reference masks the token as `rc-local-••••••••3f9a`, keeping a prefix and a four-character tail. WorkOS uses the same shape, so the design reference holds here.
3. The design reference offers Copy but never Reveal. Copy alone is defensible for a local token, and it keeps the secret off the screen. Worth a decision at the brainstorm rather than a silent addition.
4. No reference screen shows a success confirmation after Copy. Both Clay and Hume AI confirm the regeneration. The screen needs feedback for both acts.
