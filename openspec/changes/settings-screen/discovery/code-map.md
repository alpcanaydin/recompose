# Code map

- `packages/contracts/src/settings.ts` (packages/contracts (cross-process contract, outside the renderer FSD tree)) — symbols: SETTINGS_VERSION, settingsSchema, Settings, settingsMigrations, loadSettings, defaultSettings. The settings schema itself; SETTINGS_VERSION moves to 2, the strict object gains the screen's fields, and settingsMigrations goes from an empty array to holding the first v1 to v2 step.
- `packages/contracts/src/migration.ts` (packages/contracts (cross-process contract, outside the renderer FSD tree)) — symbols: Migration, migrateDocument, readSchemaVersion. The stepwise migration engine the new settings migration plugs into, unchanged but load-bearing since this is its first production use.
- `packages/contracts/src/ipc.ts` (packages/contracts (cross-process contract, outside the renderer FSD tree)) — symbols: ipcChannels, ipcResult, ipcErrorSchema, IpcChannel, IpcRequest, IpcResponse, RecomposeIpc, settings:get, settings:save. The channel registry that gains the token-mint channel plus the login-item, tray, and reveal-folder channels; every new entry propagates through IpcChannel and RecomposeIpc automatically.
- `packages/contracts/src/index.ts` (packages/contracts (cross-process contract, outside the renderer FSD tree)) — symbols: ./settings, ./ipc. The package barrel every consumer imports through; new settings and channel exports reach the desktop app only via this file.
- `packages/contracts/src/settings.test.ts` (packages/contracts (cross-process contract, outside the renderer FSD tree)) — symbols: app settings, defaultSettings, loadSettings, unknown keys are rejected. The behavior spec that pins the current defaults and the v1 shape; it changes with the version bump and gains the migration scenario.
- `packages/contracts/src/ipc.test.ts` (packages/contracts (cross-process contract, outside the renderer FSD tree)) — symbols: channelNames, exactly the seven specified channels exist, no channel exists that could read a secret back. Holds the channel-count assertion that breaks on every new channel and the secret-readback invariant that a token copy channel must not violate.
- `packages/contracts/src/ipc.test-d.ts` (packages/contracts (cross-process contract, outside the renderer FSD tree)) — symbols: expectTypeOf, IpcRequest, IpcResponse, RecomposeIpc, Settings. Type-level spec for the bridge surface; new channels need matching request and response type assertions here per the type-spec rule.
- `apps/desktop/src/main/storage/settings-store.ts` (main process (outside the renderer FSD tree)) — symbols: loadSettingsFile, saveSettingsFile. The single writer for settings.json; it reads through loadSettings so the version bump reaches disk handling with no change to this file's signature.
- `apps/desktop/src/main/storage/settings-store.test.ts` (main process (outside the renderer FSD tree)) — symbols: settings store, loadSettingsFile, saveSettingsFile, schema-invalid settings are quarantined and defaults are returned. Round-trip and quarantine specs that must cover a stored v1 document migrating forward on load.
- `apps/desktop/src/main/storage/vault.ts` (main process (outside the renderer FSD tree)) — symbols: VaultDocument, setSecret, getSecret, deleteSecret, loadVaultFile, saveVaultFile, VaultNewerSchemaError. Where the gateway token lands; setSecret and getSecret already give the mint and read primitives keyed by a ref, and deleteSecret is what must not run when the token requirement turns off.
- `apps/desktop/src/main/storage/safe-storage-codec.ts` (main process (outside the renderer FSD tree)) — symbols: SecretCodec, createSafeStorageCodec, isPlaintextFallback. Encrypts the token before it reaches vault.bin; isPlaintextFallback is the Linux warning the settings screen should surface alongside the token row.
- `apps/desktop/src/main/storage/json-file.ts` (main process (outside the renderer FSD tree)) — symbols: writeJsonAtomic, readDocumentWithQuarantine, quarantineFile. Atomic write and quarantine plumbing shared by settings and vault writes; a failed migration falls through readDocumentWithQuarantine to quarantine.
- `apps/desktop/src/main/storage/initialize-storage.ts` (main process (outside the renderer FSD tree)) — symbols: StorageState, initializeStorage. Boot-time settings read; the tray and login item need this value at startup, and today its result is discarded by the caller.
- `apps/desktop/src/main/ipc/storage-ipc.ts` (main process (outside the renderer FSD tree)) — symbols: StorageIpcContext, StoragePaths, storagePathsFor, createStorageIpcHandlers, getSettings, saveSettings, openVaultForWrite, failure. The handler factory that grows the token-mint handler; storagePathsFor already resolves vaultFile and settingsFile, and openVaultForWrite is the reusable vault-open path.
- `apps/desktop/src/main/ipc/dispatch.ts` (main process (outside the renderer FSD tree)) — symbols: IpcHandlers, ipcChannelNames, dispatchIpc. ipcChannelNames is a hand-maintained literal list that must gain every new channel or registration silently skips it.
- `apps/desktop/src/main/ipc/register-ipc.ts` (main process (outside the renderer FSD tree)) — symbols: registerIpcHandlers, senderFromEvent, ipcChannelNames. Loops ipcChannelNames to bind ipcMain.handle, so new channels inherit the sender-trust gate for free.
- `apps/desktop/src/main/ipc/dispatch.test.ts` (main process (outside the renderer FSD tree)) — symbols: dispatchIpc, handlersWith. Validation and trust specs built on a settings payload; handlersWith needs an entry for each added channel.
- `apps/desktop/src/main/ipc/storage-ipc.test.ts` (main process (outside the renderer FSD tree)) — symbols: createStorageIpcHandlers, freshContext. The integration spec covering settings get and save round trips against a real temp directory, extended by the token handler.
- `apps/desktop/src/main/ipc/storage-ipc-secret-hygiene.test.ts` (main process (outside the renderer FSD tree)) — symbols: createStorageIpcHandlers, secretFragment. The natural home for the spec requirement that the written settings document never carries the token.
- `apps/desktop/src/main/index.ts` (main process (outside the renderer FSD tree)) — symbols: registerPermissionHandlers, onStorageCorrupt, createStorageIpcHandlers, initializeStorage, createMainWindow, window-all-closed, activate. Bootstrap that must create the tray, apply the login item at ready, and change the window-all-closed quit rule so a visible tray keeps the app alive on every platform.
- `apps/desktop/src/main/windows/main-window.ts` (main process (outside the renderer FSD tree)) — symbols: createMainWindow, applyGlassBackdrop, windowOptionsFor. The only window factory; a tray click that reopens the app calls it, matching the existing activate handler in index.ts.
- `apps/desktop/src/main/user-data-override.ts` (main process (outside the renderer FSD tree)) — symbols: resolveUserDataOverride, RECOMPOSE_USER_DATA_DIR. Defines the config folder the Data section reveals, and models the pure-function plus thin-Electron-shell pattern the login item and tray toggles should follow.
- `apps/desktop/resources/icon.png` (desktop resources (outside the renderer FSD tree)) — symbols: none. The only shipped runtime icon, imported by main-window.ts through the ?asset query; a menu bar tray needs a template variant that does not exist yet.
- `apps/desktop/src/preload/index.ts` (preload bridge (outside the renderer FSD tree)) — symbols: bridgeEntry, recompose, exposeInMainWorld, settings:get, settings:save. Every channel needs an explicit bridgeEntry line here; the frozen object is the renderer's whole view of main.
- `apps/desktop/src/preload/index.d.ts` (preload bridge (outside the renderer FSD tree)) — symbols: RecomposeIpc, Window. The global Window typing the renderer relies on; it is the one preload file dependency-cruiser lets the renderer reach.
- `apps/desktop/src/renderer/src/app/routes/__root.tsx` (app) — symbols: RouterAppContext, Route, RootLayout, NotFound, Link. The shell whose sidebar nav gains the Settings link next to Gateways and Providers.
- `apps/desktop/src/renderer/src/app/routes/providers.tsx` (app) — symbols: createFileRoute, Route, accountsQueryOptions, ProvidersPage, ensureQueryData. The exact pattern the new app/routes/settings.tsx copies: a loader warming the cache through ensureQueryData and a component pulled from the page slice public API.
- `apps/desktop/src/renderer/src/app/routeTree.gen.ts` (app) — symbols: FileRoutesByFullPath, RootRouteChildren, ProvidersRoute, FileRouteTypes. Generated by the TanStack Router vite plugin; it regenerates with a /settings entry and must never be hand edited.
- `apps/desktop/src/renderer/src/app/router.tsx` (app) — symbols: createAppRouter, AppRouterOptions, routeTree, Register. Router factory and type registration; the new route reaches type safety through the routeTree import here.
- `apps/desktop/src/renderer/src/app/router.browser.test.tsx` (app) — symbols: renderAt, createAppRouter, installFakeBridge, createMemoryHistory. Navigation specs where the settings link, the /settings loader warming the cache, and the route rendering get their coverage.
- `apps/desktop/src/renderer/src/app/styles/theme.css` (app) — symbols: --color-surface-card, --color-line-subtle, --radius-card, --text-overline, --color-accent. Tier-two design tokens the grouped rows consume; the card surface, subtle divider, card radius, and overline section headers already exist for this layout.
- `apps/desktop/src/renderer/src/app/styles/main.css` (app) — symbols: color-scheme, app-drag, app-no-drag. Hardcodes color-scheme to light dark on the root elements, so the theme setting has no application path until this file or a root class gains one.
- `apps/desktop/src/renderer/src/pages/providers/index.ts` (pages) — symbols: accountsQueryOptions, ProvidersPage. The slice public API shape the new pages/settings/index.ts must mirror, exporting the page component and its query options and nothing else.
- `apps/desktop/src/renderer/src/pages/providers/api/accounts.ts` (pages) — symbols: accountsQueryOptions, useConnectAccount, useRemoveAccount, unwrapIpcResult, invalidateQueries. The query-options plus mutation-with-invalidation pattern the settings api segment copies for read, save without a save button, and token mint.
- `apps/desktop/src/renderer/src/pages/providers/ui/providers-page.tsx` (pages) — symbols: ProvidersPage, useSuspenseQuery, AccountList, ConnectAccountForm. The one existing page that reads real data; it shows the useSuspenseQuery plus composed sections structure the four settings sections follow.
- `apps/desktop/src/renderer/src/pages/providers/ui/text-field.tsx` (pages) — symbols: TextFieldProps, TextField, onChangeValue. The only field primitive in the repo and the closest precedent for the numeric field; its onChangeValue prop naming sets the convention for the new shared controls.
- `apps/desktop/src/renderer/src/pages/providers/ui/account-kind-field.tsx` (pages) — symbols: AccountKindField, AccountKindFieldProps, accountKindSchema. A native select the segmented control generalizes; it also shows the schema-parse-on-change idiom for constrained values.
- `apps/desktop/src/renderer/src/pages/providers/ui/connect-account-form.tsx` (pages) — symbols: ConnectAccountForm, emptyDraft, TextField, AccountKindField. The counterexample worth naming: it batches a draft behind a submit button, which the settings screen explicitly rejects in favor of persisting on change.
- `apps/desktop/src/renderer/src/pages/providers/ui/text-field.stories.tsx` (pages) — symbols: meta.story, TextFieldStory, Password, useArgs. The story pattern each new shared control needs, including the useArgs trick for interactive controlled inputs.
- `apps/desktop/src/renderer/src/pages/providers/ui/providers-page.browser.test.tsx` (pages) — symbols: renderProviders, installFakeBridge, seeded. The browser-test harness the settings page specs copy, including the failure-envelope override style for surfacing errors as alerts.
- `apps/desktop/src/renderer/src/pages/gateway-canvas/ui/gateway-canvas-page.tsx` (pages) — symbols: GatewayCanvasPage, Canvas coming soon.. The placeholder canvas that the reduced wire motion row waits on, confirming that unavailable row's stated dependency.
- `apps/desktop/src/renderer/src/shared/api/index.ts` (shared) — symbols: ./ipc-result. Shows the per-segment public API rule for shared; the new shared/ui segment needs its own index.ts rather than a top-level shared barrel.
- `apps/desktop/src/renderer/src/shared/api/ipc-result.ts` (shared) — symbols: IpcResultError, unwrapIpcResult. Unwraps every bridge envelope and carries the error code the settings screen branches on for vault-unavailable and storage-failed.
- `apps/desktop/src/renderer/src/shared/testing/fake-bridge.ts` (shared) — symbols: BridgeParameters, installFakeBridge, settings:get, settings:save, emptyDocument. Already stubs settings get and save with a hardcoded v1 document; it needs a settings seed parameter and a stub for every new channel or stories and browser tests break.
- `apps/desktop/src/renderer/src/shared/testing/index.ts` (shared) — symbols: installFakeBridge, BridgeParameters. The testing segment public API consumed by both browser tests and the Storybook decorator.
- `apps/desktop/.storybook/recompose-bridge.tsx` (storybook config (outside the renderer FSD tree)) — symbols: withRecomposeBridge, installFakeBridge, BridgeParameters. The decorator that installs the fake bridge per story; a settings bridge parameter flows through here into every settings story.
- `apps/desktop/.storybook/main.ts` (storybook config (outside the renderer FSD tree)) — symbols: defineMain, stories, @renderer. The story glob already covers the whole renderer src tree, so new shared/ui stories are picked up with no config change.
- `apps/desktop/.storybook/preview.ts` (storybook config (outside the renderer FSD tree)) — symbols: definePreview, withThemeByClassName, withRecomposeBridge, scheme-light, scheme-dark. Switches themes by putting scheme-light or scheme-dark on html, which is the mechanism the app theme setting has to reproduce in the renderer.
- `apps/desktop/.storybook/preview.css` (storybook config (outside the renderer FSD tree)) — symbols: scheme-light, scheme-dark, color-scheme. The only place these two classes are defined; the app stylesheet has no equivalent, which is the gap the theme control must close.
- `apps/desktop/e2e/features/providers.feature` (e2e (outside the renderer FSD tree)) — symbols: Feature: Provider accounts, Scenario:. The Gherkin shape a new settings.feature follows for the theme change, port rejection, and token scenarios.
- `apps/desktop/e2e/steps/app.steps.ts` (e2e (outside the renderer FSD tree)) — symbols: Given, the app is on the providers screen, the app is on the gateways screen. Navigation steps that gain an equivalent for reaching the settings screen through the sidebar link.
- `apps/desktop/e2e/visual.spec.ts` (e2e (outside the renderer FSD tree)) — symbols: settleFonts, openProviders, toHaveScreenshot. Screen-level visual baselines; the settings screen adds one and needs three platform snapshots committed.
- `apps/desktop/e2e/fixtures.ts` (e2e (outside the renderer FSD tree)) — symbols: inheritedEnv, electronApp, RECOMPOSE_USER_DATA_DIR, createBdd. Isolates each run with a temp user data dir, but has no equivalent guard for login item or tray state, which touch the real operating system.
- `apps/desktop/e2e/playwright.config.ts` (e2e (outside the renderer FSD tree)) — symbols: defineBddConfig, acceptanceDir, snapshotPathTemplate, visual. Feature and step globs plus the per-platform snapshot template that new settings baselines land under.
- `apps/desktop/vitest.config.ts` (repo config (outside the renderer FSD tree)) — symbols: coverageDefaults, storybookTest, browser, unit. Its coverage exclude list names the untestable Electron shells; new tray and login item modules either join that list or split into a pure decision function plus a thin shell.
- `steiger.config.ts` (repo config (outside the renderer FSD tree)) — symbols: defineConfig, fsd.configs.recommended. Runs the recommended FSD ruleset, so the new shared/ui segment and pages/settings slice have to satisfy public API and slice significance rules.
- `.dependency-cruiser.cjs` (repo config (outside the renderer FSD tree)) — symbols: renderer-isolated, no-orphans, not-to-test. Keeps the renderer out of main and preload except the type declaration, and forbids orphan modules, so every new shared control must be imported by the settings page.
- `apps/desktop/electron.vite.config.ts` (repo config (outside the renderer FSD tree)) — symbols: tanstackRouter, routesDirectory, generatedRouteTree, cspTransform. Wires the router plugin that regenerates routeTree.gen.ts from app/routes, which is how the settings route file becomes a typed route.
