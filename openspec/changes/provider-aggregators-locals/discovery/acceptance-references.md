## The repository constraints these criteria must satisfy

Two of those decisions are exactly where aggregators and locals break, and that is the most useful finding in this brief.

## A. Aggregator accounts (OpenRouter as the reference vendor)

**A1. A models-list probe cannot prove an aggregator key is valid.** OpenRouter's model catalog is served to unauthenticated callers: the models overview page's `curl https://openrouter.ai/api/v1/models` examples carry no `Authorization` header, and the page states the API "makes the most important information about all LLMs freely available" ([OpenRouter models overview](https://openrouter.ai/docs/guides/overview/models)). A `GET /v1/models` that returns 200 therefore says nothing about the stored key, so ADR-0070's probe would report a garbage OpenRouter key as working. The authenticated substitutes are documented: `GET /api/v1/key` returns `limit`, `limit_remaining`, `limit_reset`, usage, and `is_free_tier` ([OpenRouter limits](https://openrouter.ai/docs/api-reference/limits)), and `GET /api/v1/models/user` requires a bearer token and returns only models permitted under that account's provider preferences, privacy settings, and guardrails ([list models filtered by user preferences](https://openrouter.ai/docs/api/api-reference/models/list-models-filtered-by-user-provider-preferences-privacy-settings-and-guardrails)).
_Criterion_: a wrong or revoked aggregator key produces the invalid verdict, never "works". _Verify before locking_: the public-catalog fact is inferred from unauthenticated doc examples, not from an explicit sentence. One curl with a junk bearer settles it.

**A2. "Key valid, no credit" is its own verdict.** 402 comes from account balance or a per-key cap, and OpenRouter documents that a negative balance causes 402 "including for free models". 429 comes either from platform limits (free `:free` variants: 20 requests per minute for everyone; 50 per day under 10 lifetime credits, 1000 per day at 10 or more) or from an upstream provider, in which case the error carries `provider_code` metadata ([OpenRouter limits](https://openrouter.ai/docs/api-reference/limits)).
_Criterion_: the check distinguishes auth failure, spend exhaustion, and being rate-limited at this instant. Folding all three into could-not-check, as ADR-0070 currently prescribes, leaves the person with no action.

**A3. Do not build a quota readout from success responses.** OpenRouter returns `X-RateLimit-Limit`, `X-RateLimit-Remaining`, and `X-RateLimit-Reset` only on platform-limit 429 responses; "successful responses don't carry these" ([OpenRouter limits](https://openrouter.ai/docs/api-reference/limits)). Remaining credit comes from `/api/v1/key`, not from headers.

**A4. A 200 stream can still be a failure.** If rate limiting occurs after streaming begins, the error arrives as an SSE event with `finish_reason: "error"` under an already-sent 200 ([OpenRouter limits](https://openrouter.ai/docs/api-reference/limits)).
_Criterion_: the gateway's streaming path classifies an error event inside a 200 stream as a failed request, and the usage log records it as such.

**A5. 404 "No endpoints found" is a constraint refusal, not a transient fault, and must not be retried.** Reported variants: no endpoint supporting tool use on `:free` models ([goose #3054](https://github.com/aaif-goose/goose/issues/3054)), no endpoint supporting the supplied `tool_choice` ([zed #36094](https://github.com/zed-industries/zed/issues/36094)), no endpoint matching the account's data policy (fixed at openrouter.ai/settings/privacy), and a model that was renamed or stopped being free ([opencode #10594](https://github.com/anomalyco/opencode/issues/10594), [aider #2444](https://github.com/Aider-AI/aider/issues/2444)). One client classified this 404 as success and halted its fallback chain ([openclaw #61411](https://github.com/openclaw/openclaw/issues/61411)).
_Criteria_: the message names the constraint (tool use, tool_choice, data policy, unknown model); the catalog is refetchable from the interface without restarting the app; 404 never reads as success.

**A6. 502 `provider_unavailable` is transient and must be retried with backoff.** A client that failed to retry it aborted whole sessions, and the report notes OpenRouter usually recovers within seconds ([opencode #22448](https://github.com/anomalyco/opencode/issues/22448)). OpenRouter's own failover is provider-level and on by default; model fallbacks are opt-in ([OpenRouter reliability and failover](https://openrouter.ai/blog/insights/reliability-failover/)).

**A7. Aggregator model IDs are aliases, not identities.** The lookup endpoint "resolves aliases automatically" (`anthropic/claude-3-5-sonnet` to `claude-3.5-sonnet`), while `canonical_slug` is documented as the "permanent slug for the model that never changes"; `:free` and `:thinking` are separate variant IDs ([OpenRouter models overview](https://openrouter.ai/docs/guides/overview/models)).
_Criterion_: a stored aggregator target persists `canonical_slug` beside the request `id`, and a target that has left the catalog renders as "no longer offered" rather than as a hard error at request time.

**A8. Filter on `supported_parameters` instead of discovering support by failing.** The model object carries `supported_parameters`, `context_length`, `pricing`, `architecture`, and `top_provider` ([OpenRouter models overview](https://openrouter.ai/docs/guides/overview/models)). The tool-use 404s in A5 are all cases of clients offering a model whose endpoints never supported the parameter.

**A9. The catalog is large and paginated.** OpenRouter advertises 400-plus models with public query filters (`output_modalities`, `supported_parameters`, `sort`) and pagination ([OpenRouter models overview](https://openrouter.ai/docs/guides/overview/models)).
_Criterion_: the picker searches and filters; it never renders the full catalog as a flat list.

## B. Local runtimes (Ollama, LM Studio, llama.cpp)

**B1. A local account has no credential at all.** ADR-0069's kind-split row already gives the shape: add a kind that carries no `credentialRef`, rather than storing an empty secret. Ollama and LM Studio serve loopback with no key by default (Ollama binds `127.0.0.1:11434`, per [Ollama FAQ](https://docs.ollama.com/faq); LM Studio's examples target `http://localhost:1234/v1/models`, per [LM Studio list models](https://lmstudio.ai/docs/developer/openai-compat/models)).

**B2. Never store or send `localhost` for a local target.** Node 17 and later default `--dns-result-order` to `verbatim`, so `localhost` can resolve to `::1` while Ollama listens on IPv4 only, producing `ECONNREFUSED ::1:11434` ([ollama-js #102](https://github.com/ollama/ollama-js/issues/102); [n8n Ollama common issues](https://docs.n8n.io/integrations/builtin/cluster-nodes/sub-nodes/n8n-nodes-langchain.lmollama/common-issues) prescribes `http://127.0.0.1:11434` as the fix; [Ollama FAQ](https://docs.ollama.com/faq) confirms the default bind).
_Criterion_: a pasted `localhost` host is normalized to `127.0.0.1` on save, and the stored value is what the probe uses. This is a one-line rule that removes the single most common local-provider support ticket.

**B3. Base URL normalization is acceptance-critical.** Missing `/v1` and doubled `/v1` are the most reported local misconfiguration class across clients: [mindsdb #11498](https://github.com/mindsdb/mindsdb/issues/11498) (blocks `/v1` in input, then fails to append it), [hermes-agent #7516](https://github.com/NousResearch/hermes-agent/issues/7516) (Ollama base URL without `/v1` yields 404), [mem0 #4693](https://github.com/mem0ai/mem0/issues/4693) (Groq path appended twice), [agentmemory #628](https://github.com/rohitg00/agentmemory/issues/628) (silent 404 from a double suffix), [openclaw #67532](https://github.com/openclaw/openclaw/issues/67532) (spurious `/v1` appended), [spring-ai #2255](https://github.com/spring-projects/spring-ai/issues/2255) (`//v1/...` from an unstripped slash).
_Criterion_: `http://localhost:11434`, `http://127.0.0.1:11434/`, and `http://127.0.0.1:11434/v1` all resolve to the same working models call. Strip trailing slashes, strip at most one trailing version segment, then append the vendor path.

**B4. "The server is not running" is an expected state with its own copy.** LM Studio's server is something a person starts: `lms server start`, a "run the LLM server on login" preference that keeps it alive in the tray, or the `lms daemon up` standalone daemon ([LM Studio headless](https://lmstudio.ai/docs/developer/core/headless)).
_Criterion_: a connection refusal names the runtime and the port and tells the person to start the server. It is a separate verdict from "wrong URL", from "reachable but no models", and from a timeout.

**B5. An empty model list is a healthy state.** With just-in-time loading enabled, LM Studio's `/v1/models` returns all downloaded models and inference loads them on demand; with it disabled, the endpoint returns only models already in memory ([LM Studio headless](https://lmstudio.ai/docs/developer/core/headless), [LM Studio list models](https://lmstudio.ai/docs/developer/openai-compat/models)).
_Criterion_: reachable-with-zero-models renders distinctly from unreachable, and the copy for LM Studio points at the loading mode rather than implying a broken connection.

**B6. Capability discovery does not come from the OpenAI surface on Ollama.** Ollama's `/v1/models` stubs metadata: `created` "corresponds to when the model was last modified" and `owned_by` defaults to `"library"` ([Ollama OpenAI compatibility](https://docs.ollama.com/api/openai-compatibility)). Chat-capable versus embedding-only comes from `POST /api/show`, whose `capabilities` array carries `completion`, `tools`, `vision`, `embedding`, `thinking`, and `insert`; one client's discovery reads `/api/tags`, checks `/api/show` capabilities, and returns only models Ollama reports as chat-capable ([OpenClaw Ollama provider docs](https://docs.openclaw.ai/providers/ollama)). LM Studio's `/v1/models` does carry a `capabilities` array (for example `tool_use`) from version 0.3.16 (reported via search on [LM Studio list models](https://lmstudio.ai/docs/developer/openai-compat/models); the page I fetched did not restate it, so confirm before citing the version).
_Criteria_: an embedding-only local model never appears as a routable chat target; `created` is never used to sort or age a local model.

**B7. A llama.cpp model ID may be a filesystem path.** By default `llama-server` reports the `-m` path as the model `id`; `-a, --alias` overrides it ([llama.cpp server README](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md), [discussion #8547](https://github.com/ggml-org/llama.cpp/discussions/8547), [issue #17860](https://github.com/ggml-org/llama.cpp/issues/17860) on multiple aliases).
_Criterion_: the ID is echoed back byte-for-byte in requests and displayed as reported. No slug validation, no prettifying, and no assumption of a `vendor/model` shape. Note this collides with the device-safe slug rule in `docs/adr/0059-the-slug-rule-tightens-to-a-device-safe-identifier.md`: a model ID is not a slug and must not borrow that validator.

**B8. Context length is not settable over the OpenAI-compatible surface, and overflow is silent.** Ollama documents that "context size can't be set via the OpenAI API; use a Modelfile with `PARAMETER num_ctx`" ([Ollama OpenAI compatibility](https://docs.ollama.com/api/openai-compatibility)) and that the default context window is 4096, overridable by `OLLAMA_CONTEXT_LENGTH` or per-request `num_ctx` on the native API ([Ollama FAQ](https://docs.ollama.com/faq)). Over the limit, the server drops the oldest content rather than erroring; clients have shipped the resulting "the model forgot the prompt" bug and fixed it by moving to native `/api/chat` and setting `num_ctx` from the model's context window ([openclaw #4028](https://github.com/openclaw/openclaw/issues/4028), [graphify #820](https://github.com/safishamsi/graphify/issues/820), [ollama #10974](https://github.com/ollama/ollama/issues/10974)).
_Criterion_: recompose either speaks Ollama's native `/api/chat` for local Ollama targets so it can set `num_ctx`, or it never displays a context window for a local target that it cannot actually set. This is a genuine design fork and belongs in an ADR rather than in an implementation task.

**B9. Local model residency churns underneath recompose.** Ollama keeps a model in memory for 5 minutes by default (`OLLAMA_KEEP_ALIVE`, per-request `keep_alive`, `ollama stop`) ([Ollama FAQ](https://docs.ollama.com/faq)); LM Studio auto-unloads just-in-time-loaded models after idle TTL and auto-evicts the previous model when a new one loads ([LM Studio idle TTL and auto-evict](https://lmstudio.ai/docs/developer/core/ttl-and-auto-evict)).
_Criteria_: the local probe bound is separate from the cloud probe bound, because a cold load can dominate the first call; a slow first token is never reported as an unhealthy target; a target that listed a model a minute ago and 404s now reads as "not loaded", not as "gone".

**B10. Unsupported OpenAI fields must be known per runtime, not assumed.** Ollama does not support `logprobs`, `n`, `user`, `tool_choice`, `logit_bias`, `best_of`, `echo`, image URLs (base64 only), token-array embedding input, or the stateful Responses fields (`previous_response_id`, `conversation`, `truncation`); `/v1/responses` arrived only in Ollama v0.13.3 ([Ollama OpenAI compatibility](https://docs.ollama.com/api/openai-compatibility)).
_Criterion_: the local target advertises a capability set, and recompose never forwards a field the target's family does not implement. Note `tool_choice` is unsupported on Ollama and is also the exact field behind an OpenRouter 404 (A5), so it deserves a single cross-vendor rule.

## C. Cross-cutting criteria that touch the accepted records

**C1. The probe verdict vocabulary has to widen.** ADR-0070's three-way answer (works, invalid, could-not-check) was sized for one credentialed cloud vendor. Aggregators add "valid but out of credit" (A2) and "rate-limited right now" (A2). Locals add "unreachable, refused", "unreachable, timed out", "reachable, no models" (B4, B5), and "reachable, model not loaded" (B9). Every client defect above is a flattened verdict that left the person guessing. Widening the verdict union is the highest-value single change in this feature, and it is a change to an accepted record, so it needs a superseding or amending ADR rather than a quiet code edit.

**C2. Keep "a verdict is never stored" (ADR-0070), and keep it harder for locals.** A local server stops between two renders far more often than a cloud key gets revoked, so a cached "healthy" is a lie with an even shorter half-life than the revocation case that record was written for.

**C3. The probe stays in the engine child.** ADR-0070's `desktop-not-into-engine` boundary in `.dependency-cruiser.cjs` and the vendor-dialect argument apply unchanged to two more families. Locals add a second reason: the base URL is person-supplied, so the redirect refusal and the call bound in that record become a server-side-request-forgery control, not just hygiene.
_Criterion_: a stored local base URL accepts `http` and `https` only, and a non-loopback host is a deliberate and visible choice in the interface.

## Recommendation

1. **Split the probe by family instead of extending one probe.** Aggregator probe: authenticated `GET /api/v1/key` for validity and credit, plus `GET /api/v1/models/user` for the catalog the key can actually reach. Local probe: unauthenticated models list against a normalized base URL, plus the vendor's capability call (`POST /api/show` on Ollama). Both stay inside `packages/engine/src/provider/` behind the existing `probe` directive.
2. **Land the verdict widening and the base URL normalization rule as the first two tasks**, because most of the recorded defects in this brief are one of those two omissions.
3. **Open one ADR for the Ollama context question (B8)** and one for the widened verdict union (C1). Both change decisions already accepted in `docs/adr/0070-key-checks-live-in-the-engine-child.md`.
4. **Do not offer tool-calling on a target until its capability set says so** (A8, B6, B10). It is one rule serving both families.

## Where the evidence is thin or conflicting

- **Ollama's default context window.** The FAQ states 4096; community writing reports the Modelfile baseline as 2048 and the runtime as choosing dynamically by available VRAM. Treat 4096 as documented, not guaranteed, and do not display a number recompose did not set.
- **OpenRouter's public catalog (A1).** Rests on unauthenticated curl examples in the docs, not an explicit statement. One curl settles it, and the whole aggregator probe design depends on the answer.
- **LM Studio's server default state.** The headless page describes how to start and persist the server but never states whether it is off on a fresh install, so B4's copy should not assert a default.
- **LM Studio `capabilities` since 0.3.16.** Came from search summary, not from the page body I fetched.
- **Repository grounding.** No proposal, spec, or probe source could be opened (see gap 1), so any criterion above may already be stated, or contradicted, inside `openspec/changes/provider-aggregators-locals/`. A follow-up pass with file search should reconcile the two before these land as acceptance criteria.
