# The first gateway and the engine that serves it

## Why

recompose holds a gateway contract and two channels that carry gateway documents across the process boundary. Nothing creates a gateway, nothing lists one, and no server answers anywhere. The canvas route renders a placeholder.

This change closes the loop end to end. A person creates a gateway from the empty state, sees it in the sidebar, and starts it from the toolbar. The gateway answers at the root of its own loopback address. A model request answers with a typed refusal that names the missing model, in a shape a client SDK can read, because no provider connects to a gateway yet.

## What changes

- The home empty state gains a "Create your first gateway" call to action.
- A creation sheet takes a display name, a slug, and a port. The port field arrives filled with a free port that the main process offers. A live "Serves at" preview follows every keystroke in the port field.
- A new gateway serves the moment it saves. One that loses its port between the offer and the save stores anyway and shows as stopped beside its failure.
- The sidebar lists every saved gateway. Each row trails a status indicator whose shape, not only its color, carries the state.
- The toolbar becomes a real container instead of a bare drag strip. It gains a start and stop control, a monospace address pill, and a copy affordance that runs in the renderer.
- A get-started checklist card coaches the first session and names what its waiting steps wait for.
- A new `packages/engine` package holds a Hono app served through `@hono/node-server`. Each gateway owns its own loopback port and answers at the root of its own address, which supersedes Architecture Decision Record (ADR) 0005.
- The engine runs as one resident utility process child. Start and stop open and close per-gateway listeners inside it, and per-gateway state pushes to the screen over a new event surface.
- `gatewayConfigSchema` accepts an empty `virtualModels` array and gains a `port` field at version 1. The slug rule tightens with a length bound and a Windows device-name refusal, and reserves nothing.
- The settings screen loses the port outright, and its two inert server rows stop claiming to wait on the engine.
- The menu bar menu lists every gateway, each carrying a submenu of start, stop, and restart. Restart composes stop then start in the main process.
- The application menu gains a "New Gateway…" item at CmdOrCtrl+N, the keyboard path the gateways spec requires, and a "Show Get Started" item under View.

## Locked decisions

The brainstorm settled every decision below, and this document records them so later phases don't reopen them.

### Maintainer decisions

- **The change runs the full tier with no override.** The gateway contract, a new engine subsystem, the process boundary, and three renderer slices all change together.
- **The scope adds the pill and the checklist, and the canvas node stays out.** The change covers the empty-state call to action, the creation sheet with its live preview, the sidebar rows with their status indicators, the start and stop control, the toolbar address pill with copy, and the get-started checklist. The canvas gateway node card stays out, so the canvas keeps its placeholder. The reference's "Read the guide" button, its shortcut hint, and its bottom status bar also stay out, because the approval names only the pill and the checklist as additions.
- **Each gateway owns its own loopback port and answers at the root of its own address.** This supersedes ADR-0005, whose shared port left per-gateway start and stop at routing level and left the per-gateway status dot mirroring one engine state. A taken port now fails one gateway alone, a failure-isolation gain the shared design couldn't offer. Four pieces of the shared design leave with it, and each deletion buys something. First-segment slug routing leaves, so the copied address is a bare origin that survives every SDK's base-URL concatenation. Reserved slug names leave, so no naming rule ever invalidates a stored document. Path normalization leaves, so the engine never repairs doubled slashes or repeated segments and never answers a redirect. Dialect-by-path-suffix routing leaves, so no refusal ever guesses its envelope from a suffix.
- **The slug reservation for `v1` and `health` drops, and the length bound and Windows device-name refusal stay.** Nothing routes by path any longer, so a slug can't collide with a route. The slug stays an identifier and a filename, which is what the surviving rules protect.
- **The settings screen loses the port outright.** A port belongs to one gateway rather than to the app. This carries a modified delta against the settings capability and retires a shipped row, its browser test, an accepted scenario, and a compiled acceptance feature. The Impact section names each.
- **The sheet takes a port after all, arriving filled with a free one.** A person with no opinion never picks a port, and a person with one never fights the app. Main finds the offer by binding loopback port 0, reading the port the operating system assigned, closing the probe, and skipping ports stored gateways hold.
- **A new gateway serves the moment it saves.** One that loses its port between the offer and the save stores anyway and shows as stopped beside its failure.
- **The menu bar lists every gateway, each with a submenu of start, stop, and restart carrying icons.** An entry the gateway's state rules out renders unavailable rather than disappearing, so the submenu keeps one shape as state changes.
- **Gateway settings is a separate feature.** Nothing in this change edits a name, a slug, or a port after creation.
- **A failed start offers to move the gateway to a free port.** With editing deferred to the gateway settings feature, the offer is the only recovery this change ships for a squatted port, which makes it load-bearing rather than optional.
- **A failed start reads as stopped plus an error line.** The indicator stays binary. A start that loses its port shows the stopped shape, and a separate error line names the taken port.
- **The engine serves over Hono and `@hono/node-server`.** The choice buys port-free behavior specs: every routing and refusal behavior runs through `app.request()` with no socket, which is what the testing rules ask for. This revisits the line ADR-0002 drew, that Node's `http` suffices, and lands as its own ADR.
- **`gatewayConfigSchema` stays at version 1 with no migration.** Dropping the non-empty bound widens the accepted set, and the new `port` field lands in the same version. Backward compatibility constrains nothing anywhere in this change, because recompose has no release and no stored document.
- **A failed start travels inside the engine state union.** The invoke response and the push payload share one per-gateway state shape, and a failed start answers `ok: true` carrying `{ status: 'stopped', failure: { port } }` rather than an `ipcErrorSchema` code. The honest cost: every other expected failure in `packages/contracts/src/ipc.ts` crosses the boundary as `ok: false` with a code, so this surface now carries two failure vocabularies. The single representation won because the indicator, the error line, and the push all read one value, and a state that arrives by invoke can never disagree with one that arrives by push.
- **The contracts cluster lands alone first and opens with two spikes.** The dependency-cruiser verdict on the `?modulePath` import, settled by running `pnpm run lint:boundaries`, and the `@hono/node-server` adapter under the Electron utility process both run before any cluster builds on them. Neither risk waits for integration.
- **The story suite gains a second scheme in this change.** A dark vitest project lands beside the light one, plus an assertion that the requested scheme applied. `apps/desktop/vitest.config.ts` runs one storybook project today, and the components this change adds include one whose only job is to carry a state color.
- **One resident engine child, and the copy runs in the renderer.** The child survives across start and stop, opening and closing per-gateway listeners inside itself. The address carries no secret, so the copy affordance runs in the renderer, and the vault precedent from ADR-0047 stays scoped to secrecy.

### Project-level decisions

These predate the change and come from accepted ADRs. ADR-0005 no longer appears here, because the port decision above supersedes it.

- **The engine is pure TypeScript in a utility process.** ADR-0002 places the engine in `packages/engine` with zero Electron imports, run in an Electron `utilityProcess`. This change revisits its transport line only, and the placement holds. `.dependency-cruiser.cjs` pre-staged the walls before the package existed: `engine-no-electron`, `engine-only-contracts`, and `desktop-not-into-engine`.
- **Paid accounts stay behind loopback.** ADR-0047 records the posture in the project's own words: a gateway serving a local network hands the quota to whoever asks. `requireGatewayToken` stays unread this round, recorded as a named deferral rather than an omission.

### Converged decisions

All three candidate approaches arrived at the same answers below. Where the port decision changed a premise, the entry says what moved.

- **A pure Hono app with one socket-touching module.** The app composes as a pure function over Request and Response. The module split: a loopback guard, refusal envelope builders, the app composition, one listener module that alone touches sockets, and one impure child entry.
- **Dual-family loopback bind, now per gateway.** Each gateway's listener binds the literal `127.0.0.1` always and opens `::1` alongside it, never the string `localhost`. A machine with no IPv6 loopback degrades to IPv4 rather than failing. `EADDRINUSE` on either family fails that gateway's start alone, and the error listener attaches before `listen`. The engine spec's per-gateway listener reads as one request handler across up to two sockets.
- **Host and Origin guard.** The engine rejects any request whose `Host` falls outside the loopback set for that gateway's port, and any request carrying an `Origin` header at all. Both answer 403. No browser has business here, and no command-line client sends an origin.
- **Fixed root routes replace first-segment routing.** Each gateway's app serves `GET /health` plus the two dialect endpoints, answering the dialect paths with and without the `v1` prefix so either SDK habit lands on a bare origin.
- **Each dialect route owns its envelope.** Both refusals answer 404 with a JSON content type. The dialect routes answer their own vendor envelope by construction, and every other path answers the Anthropic envelope, the only vendor-published shape.
- **The health path.** `GET /health` answers 200 carrying the gateway's name. No liveness and readiness split.
- **Stop closes, then drains.** `close()` runs first, then `closeAllConnections()`, and stop resolves only once that gateway's listeners are down. Start while running and stop while stopped are both no-ops.
- **Main owns storage.** The engine receives the gateway list, each entry carrying its port, as data over the message port and never touches a filesystem.
- **An `ipcEvents` sibling map.** The lifecycle push gets its own map beside `ipcChannels` in `packages/contracts/src/ipc.ts`, because folding it in would break the request-to-response shape of `RecomposeIpc`.
- **The preload disposer.** Preload exposes a second frozen global whose entry wraps the callback, so `ipcRenderer` never leaks through `event.sender`, and every subscription returns an unsubscribe.
- **The `settingsQueryOptions` move dies with its reason.** The move to `shared/api` existed so the sheet could read the stored port. The sheet now takes its own port, so the query stays in `apps/desktop/src/renderer/src/pages/settings/api/settings.ts` and the Steiger cross-import hazard never forms.
- **The `widgets` layer opens.** The renderer holds `app`, `pages`, and `shared` today. A gateway sidebar widget and a gateway toolbar widget become the new layer's first slices.
- **Push writes into the query cache.** Per-gateway state lands through `setQueryData` on an engine-state key rather than an invalidation, and the gateway list stays untouched.
- **The duplicate-slug fix lands in main, and the port conflict joins it.** `saveGatewayConfig` in `apps/desktop/src/main/storage/gateway-store.ts` overwrites a matching file without a check, and a renderer list can be stale, so main enforces the slug conflict with a typed code. The two-gateways-never-share-a-port rule enforces in main for the same reason, with its own code.
- **The slug rule tightens in contracts.** A 63-character bound and a Windows device-name refusal join `gatewaySlugSchema` in `packages/contracts/src/gateway-config.ts`, so the sheet and main share one rule by construction.

## Layout contract

The dashed ghost graph sits above the call to action: an inline SVG, `aria-hidden`, at an intrinsic 436 by 96 pixels and opacity 0.75, drawn as two dashed node outlines labelled Gateway and Virtual Model joined by a dashed path, stroked 1 pixel in `--color-line-strong`. ## Design-system gap analysis

Each gap below names the verified state and what closes it.

### The running state has no token, and the obvious value fails

`apps/desktop/src/renderer/src/app/styles/theme.css` carries accent, warning, danger, and danger-ink, and nothing green. ADR-0053 removed `--color-success` because nothing painted with it. `--green-500` and `--green-600` survive unmapped in `apps/desktop/src/renderer/src/app/styles/primitives.css`, and mapping them as `light-dark(var(--green-600), var(--green-500))` fails in light. There `--green-600` measures 1.97 to 1 against the sidebar and `--color-ink-tertiary` measures 1.98 to 1, so running and stopped would share one lightness. ADR-0053's Consequences instruct picking the value against a real background.

What closes it: a new primitive `--green-700: #1a9e33`, the light value ADR-0053 records for the locked flow green. One semantic reads it, written `--color-running: light-dark(var(--green-700), var(--green-500))` beside its neighbors per the add-the-semantic-line rule in ADR-0009. Light measures 3.26 to 1 against the sidebar, which clears the 3 to 1 that Success Criterion 1.4.11 asks of a graphical object. The token names the running state rather than success or flow, because ADR-0053 reserves flow green for canvas live traffic. Sharing a primitive value stays a coincidence of palettes, exactly as that ADR reads it, and the canvas mints its own token when live traffic exists.

### No sheet primitive and no status indicator exist

`apps/desktop/src/renderer/src/shared/ui/` holds the field group, the field row, the labelled text field, the numeric field, the page error, place focus, the segmented control, the switch, and the text field. It holds no dialog, no sheet, no scrim, and no status indicator. The settings change confirmed a regeneration inline to avoid building a dialog primitive, and the creation sheet is the surface that earns one.

What closes it: a sheet primitive on the Base UI dialog per ADR-0044, carrying `initialFocus`, and a status indicator. The indicator pairs the filled-versus-hollow shape with the state word as its accessible name. Both export through `shared/ui/index.ts` with story siblings. The scrim lands as two black alpha primitives and one semantic written `light-dark(...)`, because neither token file carries an overlay value today.

### No elevation token exists

`theme.css` carries one shadow, `--shadow-thumb`, sized for a switch thumb. The sheet and the checklist are the project's first floating surfaces. In dark a card measures 1.16 to 1 against the canvas, so a shadow alone can't separate them.

What closes it: one semantic elevation token, `--shadow-raised`, a soft wide shadow over a hairline edge, consumed by the sheet and the checklist and paired in dark with a `--color-line-subtle` border.

### No primary filled button exists

The kit's only button voice is the neutral `push-button` utility, and the empty state's call to action needs a filled primary. What closes it: a filled sibling utility beside `push-button`, accent fill with a white label at the control size, hover on `--color-accent-hover`. The empty state and the sheet footer are its only consumers. The frontend rules require measuring the label against the fill from the page, in both schemes, before it lands.

### The renderer draws no icon

No component under `apps/desktop/src/renderer/src` renders an SVG. What closes it: the ghost graph lands as one `aria-hidden` inline SVG, the ring markers render as styled circles, and the buttons and rows ship text only. The copy button carries one inline glyph plus its check swap in its own component. No icon system lands, because one glyph doesn't earn one.

### The menu bar has no lifecycle machinery

`apps/desktop/resources/` holds `icon.png`, `tray.png`, `trayTemplate.png`, and `trayTemplate@2x.png`, and no start, stop, or restart asset of any kind. `TrayMenuItem` in `tray-menu-template.ts` carries no submenu and no icon, and `menu-bar-tray.ts` sets the context menu once at creation, so the menu could never follow state.

What closes it: three lifecycle template images with `@2x` variants under `apps/desktop/resources/`, following the tray-asset precedent from the settings change. `TrayMenuItem` grows submenu, icon, and enabled fields, and the template function stays pure. The tray rebuilds its context menu on every lifecycle push and list change, so the menu follows gateway state without a person reopening it.

### The checklist outruns the machinery

The reference card tracks four steps, and the discovery records its geometry and markers without naming the steps. This design fixes them against what exists. Create a gateway completes in this change. Connect a provider completes today through `apps/desktop/src/renderer/src/pages/providers/`, which already connects an account. Compose a virtual model waits on the canvas, which renders "Canvas coming soon." in `apps/desktop/src/renderer/src/pages/gateway-canvas/ui/gateway-canvas-page.tsx`. Send the first request waits on a virtual model, because a model request answers a typed refusal until one exists.

The two waiting steps render as pending rows that name what they wait for, mirroring the settings screen's waiting rows. The card advances past step one for real, through the provider step, so it coaches rather than stalls. Step state derives from stored documents, a gateway exists and an account exists, rather than from its own record. "Skip setup" hides the card. The dismissal persists in `localStorage` under a named renderer key, because the checklist is coaching chrome rather than domain data and the settings document stays untouched. The View menu's "Show Get Started" item clears the key and brings the card back.

## Capabilities

### New capabilities

- `gateways`: a person creates, names, and lists a gateway, reaches every gateway from the menu bar, and the app shows whether each one serves.
- `engine`: each gateway answers on its own loopback port at the root of its own address, and the engine reports per-gateway state to the app.

### Modified capabilities

- `settings`: the screen loses the port, because a port belongs to one gateway rather than to the app. The delta lives at `openspec/changes/first-gateway-and-engine/specs/settings/spec.md`.

## Impact

- The gateway contract stops requiring a virtual model and gains a `port` field, both at version 1 with no migration. Every consumer that reads `virtualModels[0]` faces an empty array, and the fast-check arbitrary in `packages/contracts/src/gateway-config.test.ts` moves with both changes.
