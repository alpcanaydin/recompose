# Code map

- `openspec/changes/app-icon/specs/app-icon/spec.md` (openspec artifact (outside FSD)) — symbols: The packaged app carries the recompose mark, macOS 26 renders the icon as Liquid Glass, The menu bar shows the note glyph alone. The three requirements that scope this map: packaged-artifact identity, the macOS 26 Icon Composer asset, and the note-glyph-only tray icon.
- `openspec/changes/app-icon/manifest.md` (openspec artifact (outside FSD)) — symbols: tier, phase, approvals, branch. Records the standard tier and the approval note that the work stays in packaging and assets with one bounded code touch for the Linux window icon.
- `openspec/changes/app-icon/discovery/mark.svg` (openspec artifact (outside FSD)) — symbols: paint2_linear_2_38, clip0_2_38. The master vector mark the sibling design arm placed; paint2_linear_2_38 fills the note glyph path, so the tray variants derive from that path alone.
- `apps/desktop/electron-builder.yml` (packaging config (outside FSD)) — symbols: appId, productName, directories, buildResources, afterPack, asarUnpack, mac, dmg, nsis, linux, entitlementsInherit. GAP: the file carries no icon key at all, so electron-builder resolves icons purely by the build/ filename convention; mac.extendInfo, CFBundleIconName, nsis.installerIcon and dmg.icon do not exist yet and are net-new keys here.
- `apps/desktop/build/icon.icns` (build resources (outside FSD)) — symbols: none. The macOS legacy bitmap icon, still the stock Electron art from commit 3c20c6e; file reports a lone ic09 (512x512) member, so the replacement needs the fuller size ladder the dock asks for.
- `apps/desktop/build/icon.ico` (build resources (outside FSD)) — symbols: none. The Windows icon, stock Electron art carrying six sizes from 16x16 up; it feeds the taskbar, the desktop shortcut and the window frame in the installer scenario.
- `apps/desktop/build/icon.png` (build resources (outside FSD)) — symbols: none. The 512x512 Linux packaging icon; byte-identical to apps/desktop/resources/icon.png (md5 a2cf889708d9c4959c6808b4584848e4), so two copies of the stock art need replacing and the pair is a sync hazard.
- `apps/desktop/build/after-pack.cjs` (build resources (outside FSD)) — symbols: afterPack, binaryPath, fuseFlags, flipFuses, resetAdHocDarwinSignature. The only bundle post-processing hook, and the only place a compiled Icon Composer Assets.car could be dropped into Contents/Resources; resetAdHocDarwinSignature already handles the re-sign that any post-pack bundle edit forces.
- `apps/desktop/build/entitlements.mac.plist` (build resources (outside FSD)) — symbols: com.apple.security.cs.allow-jit. The only committed plist, referenced by mac.entitlementsInherit; the icon Info.plist key does not belong here, it goes through mac.extendInfo in electron-builder.yml.
- `apps/desktop/resources/icon.png` (runtime resources (outside FSD)) — symbols: none. The 512x512 runtime window icon, imported through ?asset by main-window.ts and unpacked from the asar by the asarUnpack resources rule; currently stock Electron art.
- `apps/desktop/resources/tray.png` (runtime resources (outside FSD)) — symbols: none. GAP: the 32x32 coloured tray asset shows a two-node link glyph, not the note glyph, so the Windows and Linux notification-area requirement is a replacement rather than a no-op.
- `apps/desktop/resources/trayTemplate.png` (runtime resources (outside FSD)) — symbols: none. The 16x16 macOS template asset the menu bar tints; carries the same link glyph and needs the thickened note geometry instead.
- `apps/desktop/resources/trayTemplate@2x.png` (runtime resources (outside FSD)) — symbols: none. The 32x32 retina template representation added at scaleFactor 2 by menu-bar-tray.ts; replaced alongside its 1x sibling.
- `apps/desktop/src/main/tray/tray-icon.ts` (main process (outside FSD)) — symbols: trayIconFor, TrayIconSources, TrayIcon. The pure platform-to-icon decision that already encodes the spec's template-on-macOS and coloured-elsewhere split, so the tray requirement needs new art rather than new branching here.
- `apps/desktop/src/main/tray/tray-icon.test.ts` (main process test (outside FSD)) — symbols: trayIconFor, anyPlatform, sources. The behavior and property specs pinning the template flag, the source and the retina representation to darwin; they change only if the platform split changes.
- `apps/desktop/src/main/tray/menu-bar-tray.ts` (main process (outside FSD)) — symbols: trayIcon, showMenuBarTray, hideMenuBarTray, isMenuBarTrayVisible. Holds the three ?asset imports plus the nativeImage.createFromPath, addRepresentation and setTemplateImage wiring; excluded from both coverage and mutation, so no new logic may land here.
- `apps/desktop/src/main/tray/tray-menu-template.ts` (main process (outside FSD)) — symbols: buildTrayMenuTemplate, TrayMenuHandlers, TrayMenuItem. The menu behind the tray icon; unaffected by a glyph swap but named because showMenuBarTray composes it with trayIcon in one call.
- `apps/desktop/src/main/windows/window-options.ts` (main process (outside FSD)) — symbols: windowOptionsFor. The one bounded code touch the manifest anticipates: the Linux-only icon branch that puts the mark on the window frame, and the darwin branch that deliberately omits it.
- `apps/desktop/src/main/windows/window-options.test.ts` (main process test (outside FSD)) — symbols: windowOptionsFor, someIcon, anyPlatform. Pins options.icon to Linux only across every platform, so any change to where the window icon applies must move these specs first.
- `apps/desktop/src/main/windows/main-window.ts` (main process (outside FSD)) — symbols: createMainWindow, HOME_ROUTE, showMainWindow, openSettingsSurface, applyGlassBackdrop. Imports resources/icon.png through ?asset and hands it to windowOptionsFor; excluded from coverage and mutation, so it stays pure wiring.
- `apps/desktop/src/main/index.ts` (main process (outside FSD)) — symbols: startRecompose, trayMenuHandlers, settingsEffects. Calls electronApp.setAppUserModelId('sh.recompose.app'), which is what binds the pinned Windows taskbar icon to the right app identity in the installer scenario.
- `apps/desktop/src/main/settings/apply-settings.ts` (main process (outside FSD)) — symbols: SettingsEffects, applyChosenSettings, applyBootSettings. setMenuBarVisible is what creates or destroys the tray, so the note-glyph requirement only becomes observable while the menu bar setting is on.
- `apps/desktop/electron.vite.config.ts` (build config (outside FSD)) — symbols: cspTransform, injectContentSecurityPolicy, defineConfig. The main block is empty, so ?asset resolution rides electron-vite defaults and a new tray or icon asset needs no config change here.
- `.dependency-cruiser.cjs` (quality gate config (outside FSD)) — symbols: not-to-unresolvable, no-orphans, no-phantom-deps. not-to-unresolvable exempts paths matching \?asset$, which is what lets new asset imports pass; no-orphans would flag any new icon module nothing imports.
- `apps/desktop/vitest.config.ts` (quality gate config (outside FSD)) — symbols: coverageDefaults. The coverage exclude list names src/main/tray/menu-bar-tray.ts and src/main/windows/main-window.ts, so testable icon logic must land in a pure sibling module instead.
- `apps/desktop/stryker.config.json` (quality gate config (outside FSD)) — symbols: mutate, thresholds. The mutate list repeats the same two exclusions and breaks at 81, so node-side icon logic added outside those files must survive the diff-scoped gate.
- `knip.json` (quality gate config (outside FSD)) — symbols: entry. The apps/desktop entry list registers build/after-pack.cjs; any new icon build script needs registering here or knip reports it unused.
- `cspell-words.txt` (quality gate config (outside FSD)) — symbols: asar, nsis, dmgbuild. The committed accept list already carries the packaging vocabulary; new icon words land here in the same diff to clear the spelling gate.
- `apps/desktop/e2e/packaged-smoke.spec.ts` (e2e (outside FSD)) — symbols: createPackagedLaunchEnv, trackChildFailure, parseElectronApp, findLatestBuild. GAP: the only packaged-artifact proof asserts the asar flag and two fuses and carries no icon assertion, so an artifact-level icon check is net-new here.
- `apps/desktop/e2e/playwright.config.ts` (e2e (outside FSD)) — symbols: defineBddConfig, acceptanceDir, snapshotPathTemplate. Defines the packaged project that runs packaged-smoke.spec.ts under a 120 second timeout, the only lane where a built bundle is available to inspect.
- `apps/desktop/e2e/steps/settings-menu-bar-presence.steps.ts` (e2e (outside FSD)) — symbols: trayStandsInMenuBar, menuBarSwitch, menuBarSwitchLabel. The existing tray steps assert presence rather than pixels, so swapping the glyph art leaves them green.
- `apps/desktop/e2e/visual.spec.ts` (e2e (outside FSD)) — symbols: pinLightScheme, settleFonts, capture. Every baseline clips to a 1024x660 content rectangle with no window frame, dock or menu bar in frame, so the screen-level snapshots are unaffected by any icon change.
- `docs/assets/icon.png` (records (outside FSD)) — symbols: none. The only rendered copy of the recompose mark on main today, a 256x256 raster serving as the README logo; it matches mark.svg, not the stock Electron art shipping in the app.
- `README.md` (records (outside FSD)) — symbols: none. Points its LOGO image at docs/assets/icon.png, which is why the README already shows the mark while every packaged artifact still shows the Electron atom.
- `.github/workflows/release.yml` (CI (outside FSD)) — symbols: build:mac, build:win, build:linux. The three-OS matrix that bakes the icons into artifacts; a macOS-only Icon Composer compile step would have to sit behind the runner.os == 'macOS' guard.
- `docs/adr/0008-liquid-glass-window-chrome.md` (records (outside FSD)) — symbols: none. The existing macOS-appearance decision whose Liquid Glass reasoning the macOS 26 icon requirement extends, and the natural precedent to cite in the new ADR.
- `docs/adr/0035-release-operations.md` (records (outside FSD)) — symbols: none. Describes the packaged artifact set and the unsigned phase A, the record that any change to bundle contents or post-pack signing has to stay consistent with.
- `docs/adr/README.md` (records (outside FSD)) — symbols: none. The ADR index table where the new icon decision registers; the last accepted entry is 0054, so the new record takes 0055.
- `docs/adr/0010-folder-structure-fsd-and-enforced-boundaries.md` (records (outside FSD)) — symbols: none. The ADR governing renderer placement; it is the reason no entry in this map sits in an FSD layer, since every touched file is packaging, assets, or main process.
- `apps/desktop/src/renderer/src/shared/ui/index.ts` (renderer: shared/ui) — symbols: FieldGroup, FieldRow, PageError, SegmentedControl, Switch. GAP: no renderer file is in scope for this spec and no FSD slice consumes the mark; this barrel is only the landing spot if the mark ever has to render in-app, and nothing in the three requirements asks for that.
