The edit-time test-first gate (ADR-0040) covers exactly the directory tree holding the `probity.config.ts` it loads: `loadConfig` rewrites `apps/*/src/**` into `<that config's directory>/apps/*/src/**` (`anchorGlob`, `node_modules/@nizos/probity/dist/config.js`), so an action path outside that root matches nothing and the gate answers with empty stdout and exit 0, which Claude Code reads as no opinion. Every scope fix so far traded that silent permit for a wider execution surface.

**Why:** Round 1 (2026-07-28) reproduced the original gap with the real binary and fixed it by walking up from the payload's `file_path`. Round 2 reproduced the residue: the walk ran to `/`, so a config anywhere above the edited file ran through jiti (gate) or as `.oxlintrc.json` `jsPlugins` (formatter). Round 3 bounded the walk with git (`repository-scope.mts`: `git rev-parse --path-format=absolute --git-common-dir --show-prefix` in the candidate directory, compared with the same query at the hook's own checkout) and pinned the binaries to the hook's checkout. Round 3 review reproduced three ways through that bound, all on the real hooks:
1. **The gitfile forge.** The candidate directory declares its own repository. Writing one text file `/tmp/x/.git` holding `gitdir: <repo>/.git` makes git report the anchor's common dir, so `/tmp/x` passes the bound. A planted `/tmp/x/.oxlintrc.json` with `jsPlugins` then executes arbitrary code through the pinned oxlint, and a planted `/tmp/x/probity.config.ts` executes through jiti and replaces the TDD rules. Write-only, so the Bash permission classifier never sees it.
2. **The symlink overshoot.** `--show-prefix` measures depth at the physical path git resolves, while `ancestorsUpTo` climbs the logical path. A symlink inside a worktree pointing deeper into that same worktree (`wt/link -> wt/a/b/c`) makes the climb overshoot the worktree root by the difference, reaching the directory holding the worktree. ADR-0040 claims the opposite ("no symlink widens the bound"). Reproduced from outside too: a shortcut symlink into a worktree subtree (`~/rc -> <wt>/apps/desktop`) makes the walk reach the worktree's parent and `/tmp`, and a planted `jsPlugins` module there ran under the pinned oxlint (exit 0, marker written). The mirror direction is the silent permit: a symlink that makes the logical path deeper than the physical one (`wt/a/b/c -> wt/apps/desktop`) makes the climb stop below the worktree root, so the worktree's own `probity.config.ts` is never seen and the gate falls back to the session checkout.
3. **The fail-open.** Any failure of the placement query (git older than 2.31, so no `--path-format`; git absent; dubious-ownership refusal; `GIT_DIR` inherited) returns `[]`, and `configurationRoot` then falls back to the session checkout's config, which anchors to the session checkout, so a worktree edit matches nothing and the gate permits in silence.
4. **The uninstalled-worktree claim is false for this repository.** ADR-0040 says pinning the binaries lets the formatter hook "format and lint a worktree that carries no install," hedged on the worktree's configuration naming no JavaScript plugin. This repository's own `.oxlintrc.json` always names two (`oxlint-plugin-react-doctor`, `@stylistic/eslint-plugin`), and oxlint resolves a plugin next to the configuration file. Every edit in a fresh worktree before `pnpm install` still exits 2, now with `Failed to load JS plugin ... Cannot find module` instead of the older, actionable `oxlint did not start in <worktree> ... ENOENT`. `hook-boundary.test.mts` certifies the property with a fixture config carrying no `jsPlugins`, so the suite stays green over behavior the product does not have.

**How to apply:** When a gate derives scope from the payload path, ask three questions in order. Who states the bound, and can the actor forge that statement with the capability the threat model grants (a file write can forge a `.git` gitfile, an `.oxlintrc.json`, a `probity.config.ts`)? Does the bound measure on a resolved path and act on an unresolved one? And what does the bound do when its probe fails: falling back to the owning checkout's config is a silent permit, not a safe default, because the anchoring makes out-of-root paths match no rule. Reproduce verdict flips end to end with the real binaries; a planted `jsPlugins` module writing a marker file proves execution, and `enforceFilenameCasing` gives a deterministic deny without spending a model call (`enforceTdd` calls the agent, so it cannot prove a scope claim).

See [[hook-exit-code-fail-open]] for the launcher-side silent permits in the same gate.
