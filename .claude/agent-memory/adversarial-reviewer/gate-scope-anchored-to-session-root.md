The edit-time test-first gate (ADR-0040) covers exactly the directory tree holding the `probity.config.ts` it loads: `loadConfig` rewrites `apps/*/src/**` into `<that config's directory>/apps/*/src/**` (`anchorGlob`, `node_modules/@nizos/probity/dist/config.js`), and the claude-code adapter builds the action path as `path.resolve(payload.cwd, tool_input.file_path)` with no realpath (`dist/vendors/posix-absolute.js`). Matching is therefore a literal string comparison between an anchored glob and an unresolved payload path. A path outside the anchor matches nothing, the gate answers empty stdout with exit 0, and Claude Code reads that as no opinion.

**Why:** Four rounds, four scope answers, each with a residue.
1. Round 1 reproduced the original gap (config anchored at the session checkout, worktree edits inert) and fixed it by walking up from the payload's `file_path`.
2. Round 2: the walk ran to `/`, so any config above the edited file executed through jiti (gate) or `.oxlintrc.json` `jsPlugins` (formatter).
3. Round 3 bounded the walk with git (`repository-scope.mts`) and pinned the binaries. Round 3's review reproduced three ways through that bound: a one-line `.git` gitfile forges membership (write-only, so the Bash classifier never sees it), `--show-prefix` measures depth on the resolved path while the climb walks the logical one (overshoot and undershoot, one with code execution), and any probe failure returns `[]`, which falls back to the session config and permits in silence.
4. Round 4 (2026-07-28, commit 01c6e30) removed the capability instead of attempting a seventh boundary. Each hook now serves only the checkout it lives in: the gate always names `<own checkout>/probity.config.ts`, the formatter always names its own `.oxlintrc.json`/`.oxfmtrc.json` and skips an edited path whose realpath is not under its realpathed root. `repository-scope.mts`, `configuration-scope.mts`, and `hook-payload.mts` are deleted.

Round 4's residue is an asymmetry between the two hooks. `format-edit.mts` realpaths both its checkout root and the edited path, so a checkout reached through a symlink is still "inside." `resolve-transcript.mts` gets a realpathed root for free (Node realpaths `import.meta.url` even for the entry script) but hands probity a literal payload path, so the same checkout is "outside" and every edit in the session gets an empty allow. Reproduced end to end with the real binary and `enforceFilenameCasing`: identical write, deny under the real path, silent permit under an alias symlink, while `format-edit.mts` blocked the same aliased file with exit 2. The pre-diff walk denied it, because it climbed the aliased path and found the config through the alias.

Verified mutation counts for ADR-0040's "every property has a case that fails without it" (run in a scratch copy of `.claude` with `node_modules` symlinked, so the real checkout stays untouched): dropping the formatter's containment check turns 3 red, making it skip every path turns 5 red, reintroducing the pre-diff formatter walk turns 6 red. Reintroducing the pre-diff gate walk turns **2** red (3 if the git bound is dropped too), not the 4 the record claims. Do not re-measure the first three.

**How to apply:** When a gate derives scope from a path, ask which side resolves. A check that realpaths and a matcher that doesn't will disagree on the same file, and the disagreement always lands on the permit side of the gate whose scope is expressed as an anchored glob. Also ask what states the bound and whether a file write can forge that statement, and what the bound does when its probe fails: falling back to the owning checkout's config is a silent permit, not a safe default. Reproduce verdict flips with the real binary; `enforceFilenameCasing` gives a deterministic deny without spending a model call (`enforceTdd` calls the agent, so it cannot prove a scope claim). The gate is now inert by decision for a subagent editing another worktree, which is the implementation phase's ordinary case, and live worktrees under `.claude/worktrees/` confirm the pattern is in use.
