The edit-time test-first gate (ADR-0040) covers exactly the directory tree holding the `probity.config.ts` it loads: `loadConfig` rewrites `apps/*/src/**` into `<that config's directory>/apps/*/src/**` (`anchorGlob`, `node_modules/@nizos/probity/dist/config.js`), and the claude-code adapter builds the action path as `path.resolve(payload.cwd, tool_input.file_path)` with no realpath (`dist/vendors/posix-absolute.js`). Matching is therefore a literal string comparison between an anchored glob and an unresolved payload path. A path outside the anchor matches nothing, the gate answers empty stdout with exit 0, and Claude Code reads that as no opinion.

**Why:** Six rounds, six scope answers, each with a residue.

1. Round 1 reproduced the original gap (config anchored at the session checkout, worktree edits inert) and fixed it by walking up from the payload's `file_path`.
2. Round 2: the walk ran to `/`, so any config above the edited file executed through jiti (gate) or `.oxlintrc.json` `jsPlugins` (formatter).
3. Round 3 bounded the walk with git (`repository-scope.mts`) and pinned the binaries. Round 3's review reproduced three ways through that bound: a one-line `.git` gitfile forges membership (write-only, so the Bash classifier never sees it), `--show-prefix` measures depth on the resolved path while the climb walks the logical one (overshoot and undershoot, one with code execution), and any probe failure returns `[]`, which falls back to the session config and permits in silence.
4. Round 4 (commit 01c6e30) removed the capability instead of attempting a seventh boundary. Each hook now serves only the checkout it lives in: the gate always names `<own checkout>/probity.config.ts`, the formatter always names its own `.oxlintrc.json`/`.oxfmtrc.json` and skips an edited path whose realpath is not under its realpathed root. `repository-scope.mts`, `configuration-scope.mts`, and `hook-payload.mts` are deleted.

   Round 4's residue is an asymmetry between the two hooks. `format-edit.mts` realpaths both its checkout root and the edited path, so a checkout reached through a symlink is still "inside." `resolve-transcript.mts` gets a realpathed root for free (Node realpaths `import.meta.url` even for the entry script) but hands probity a literal payload path, so the same checkout is "outside" and every edit in the session gets an empty allow. Reproduced end to end with the real binary and `enforceFilenameCasing`: identical write, deny under the real path, silent permit under an alias symlink, while `format-edit.mts` blocked the same aliased file with exit 2.

5. Round 5 (commit 0aeb89f) closed that asymmetry by moving the payload into the configuration's space: `physicalActionPaths` rewrote `file_path` and `notebook_path` to `physicalPath(resolve(CHECKOUT_ROOT, value))`, where `physicalPath` realpathed the longest existing prefix and rejoined the missing tail.

   **This code is deleted. Round 6 removed it, and neither `physicalActionPaths` nor `physicalPath` appears anywhere in the tree.** Read the rest of this entry as history, not as a description of the resolver.

   Round 5's residues, all reproduced against the real binary with `forbidContentPattern` (deterministic, no model call):
   - **The leaf resolves too.** A source file inside a gated glob that *is* a symlink (`apps/desktop/src/main/index.ts -> notes/index.ts`) resolved out of the glob. Pre-diff deny, post-diff empty allow. One `ln -s` bought a TDD bypass whose bytes still landed inside the checkout.
   - **A dangling leaf does not resolve.** `physicalPath` only realpathed what existed, and a `Write` target usually does not exist, so a symlink *named outside* the checkout whose target was a gated in-checkout path stayed outside: silent permit, write lands inside.
   - **`..` after a symlinked component.** `resolve()` collapses it lexically before any realpath, and `fs.realpathSync` does the same (`pathModule.resolve` first, then componentwise). `open(2)` resolves componentwise, so the write landed somewhere the gate never judged.
   - **Resolution base moved from `payload.cwd` to `CHECKOUT_ROOT`.** probity's claude-code adapter contracts `posixAbsolute(payload.cwd, file_path)`. A relative `file_path` with `cwd = <checkout>/apps/desktop` denied pre-diff and allowed post-diff.

6. Round 6 (commit 919f07d) reverted the resolver to the round-4 shape: the payload's action paths reach the vendor exactly as the payload named them, and the symlinked-prefix miss is accepted as a documented limit. The two designs miss on mutually exclusive shapes, and the branch kept the one that denied more: 3 of the 4 reproduced shapes against 1. That trade is recorded in ADR-0040 and in the `edit-time-test-first-gate` specification delta. Do not propose resolving the action path a seventh time without reading both.

**Mutation counts, and which round measured which.** Round 7 measured these against the 61-case suite it leaves behind, by swapping `resolve-transcript.mts` and running `node --test` over `gate-pipe.test.mts` and `gate-scope.test.mts` (19 of the 61):

- Reintroducing round 5's rewriting verbatim: **2 red**.
- Reintroducing it guarded on `isAbsolute`: **1 red**.
- Reintroducing it anchored on `payload.cwd`, leaving the path alone when the payload names no `cwd`: **2 red**.
- Replacing the formatter's resolved containment comparison with a plain one: **2 red** on the full 61.

Round 7 had to measure at all because the single case round 6 left behind used a fixture the vendor rejects: relative `file_path`, no `cwd`, no `content`, while probity 1.10.0's `writeSchema` requires `cwd` as a non-empty string and `tool_input.content` as a string. The real binary answers that fixture `Probity: invalid hook payload: Invalid input: expected string, received undefined`. Measured against the 18 gate cases that fixture drove, the absolute-guarded shape left all 18 green and the cwd-anchored shape left all 18 green. Only the naive shape went red. Two cases now carry the property, driven by payloads the binary accepts: one names the edited file through a symbolic link, the other leaves the path relative to a working directory that is not the checkout root.

**Counts round 7 did not re-measure**, carried from the round that did, each attached to a suite composition that no longer exists. Round 5's suite (a different 61) read formatter containment dropped 4 red and formatter skip-every-path 6 red. Round 4's suite read formatter containment dropped 3 red, skip-every-path 5 red, pre-diff formatter walk 6 red, and pre-diff gate walk 2 red (3 unbounded), not the 4 that record first claimed. Re-measure before citing any of them.

**Round 7's review (2026-07-28, commit bcb8a32) re-verified the round's claims and found the new pin evadable three ways.** Both review seats reproduced the first two independently. Verified against the real tree: 61/61 green, probity 1.10.0 accepts the new fixture (deterministic `forbidContentPattern` deny in-anchor, empty allow out-of-anchor, and the old fixture reproduces the quoted parse-error deny), the 2/1/2 mutation counts reproduce exactly, the pre-diff 18-green readings for the absolute-guarded shape reproduce, the formatter plain-comparison breakage still reads 2 red on the 61, and all six resolution claims in ADR-0040's `..` paragraph reproduce (build the fixture path by string concatenation; `path.join` collapses the `..` before any resolver sees it and fakes a contradiction). The three residues, all reproduced:

- **Existence-guarded rewriting slips both cases.** Neither pass-through fixture creates `apps/desktop/src/main/index.ts` or the `apps/desktop` working directory, so every pinned path is dangling. A reintroduction guarded on `isAbsolute(value)` plus `try { realpathSync } catch { return path }` leaves all 19 gate cases green while rewriting every real edit of an existing file (the ordinary Edit case; probity's editSchema even requires the file to exist via `applyEdit`). Creating the target file inside the aliased-case fixture turns that shape red.
- **`notebook_path` pass-through is unpinned.** Round 5's rewriting covered `file_path` and `notebook_path`; the notebook case left with the rewriting and both replacement cases drive `file_path` only. A reintroduction rewriting only `notebook_path` passes all 19, and nothing else in the 61 reaches the resolver's payload handling (`hook-boundary` is the formatter suite, `resolve-transcript.test.mts` unit-tests transcript resolution). Confirmed on the full 61, not just the 19.
- **The fixture's vendor-acceptability, the property the round exists to establish, is pinned by nothing.** No gate case runs the real binary; both pass-through cases drive the stand-in shell gate `cat stdin.json`, so the schema never gets consulted. Deleting `cwd` and `content` back out of `editPayloadFromWorkingDirectory` leaves 61/61 green, and with `cwd` gone the working-directory-anchored mutation falls from 2 red to 0. One fixture edit nobody's suite can see restores round 6's blind state exactly.

**How to apply:** When a gate derives scope from a path, ask which side resolves, and then ask it again per path component: prefix, leaf, and `..`. A check that realpaths and a matcher that doesn't will disagree on the same file, and the disagreement always lands on the permit side of the gate whose scope is expressed as an anchored glob. Resolving the leaf is not free either, because it moves a symlinked in-scope file out of the glob.

Check the fixture against the vendor's schema before trusting any case built on it. A payload the vendor rejects exercises the parse error and nothing else, so every mutation downstream of the parse survives, and the case still reads green forever. Round 6 shipped exactly that and it took a reviewer's mutation run to see it.

`fs.realpathSync.native` is the one function that carries `..` past a symlinked component into the physical space, but it delegates to `realpath(3)` and answers `ENOENT` as soon as any component is missing, the last one included. A write target that does not exist yet is the ordinary case for this gate, so a bare swap to `.native` denies every new file. Reaching that shape needs the longest-existing-prefix helper built on `.native` **and** the path handed over before `path.resolve` collapses the `..`.

Also watch the fixture side: a `before()` that plants a `symlinkSync` in the repository root is not idempotent, so one aborted run wedges every later run with EEXIST, unlike the `writeFileSync` fixtures beside it. Also ask what states the bound and whether a file write can forge that statement, and what the bound does when its probe fails: falling back to the owning checkout's config is a silent permit, not a safe default. Reproduce verdict flips with the real binary; `enforceFilenameCasing` and `forbidContentPattern` give a deterministic deny without spending a model call (`enforceTdd` calls the agent, so it cannot prove a scope claim). The gate is inert by decision for a subagent editing another worktree, which is the implementation phase's ordinary case, and live worktrees under `.claude/worktrees/` confirm the pattern is in use.
