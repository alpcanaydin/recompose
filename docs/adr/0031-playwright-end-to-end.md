# 0031: Playwright end-to-end testing, the three-platform matrix, and the quarantine policy

**Status**: Accepted
**Date**: 2026-07-25

## Context

The ninth infrastructure-queue item needed an end-to-end testing layer. The maintainer confirmed during the brainstorm that the desktop app ships to macOS, Windows, and Linux. The layer therefore runs a full three-platform matrix instead of the macOS-only shape an earlier rider assumed. Before this job, the only end-to-end artifact was `apps/desktop/e2e/security-boot-proof.mjs`, a local-only script that launched the built `out/` bundle and proved the security baseline. GitHub issue #58 asked for a packaged-artifact smoke test that a source-mode proof can't provide. The acceptance layer needed Gherkin `.feature` files as the maintainer's approval artifact. Architecture Decision Record (ADR) 0018, the typed Inter-Process Communication (IPC) job, already set that standard. Two skills already landed on this branch as groundwork before implementation started: the vendored `playwright-best-practices` skill and the authored `gherkin-best-practices` skill. A new CLAUDE.md rule makes both mandatory for end-to-end work. The Playwright Model Context Protocol (MCP) server landed too, pinned at project scope.

## Decision

- **playwright-bdd 9 runs on Playwright's native runner, not the Cucumber runner.** Gherkin `.feature` files compile through `defineBddConfig` into Playwright test files, so scenarios keep fixtures, traces, retries, and parallel workers. The Cucumber runner drops every one of those, so it stays out. Generation stays explicit rather than automatic: the `test:e2e` and `test:e2e:quarantine` scripts each run `bddgen` before `playwright test`.
- **The required `e2e` job runs a full three-platform matrix: `macos-latest`, `windows-latest`, and `ubuntu-latest`.** The matrix covers every platform the app ships to, since the maintainer confirmed macOS, Windows, and Linux during the brainstorm. The job joins the `ci-success` needs list, the same required-check pattern ADR-0007 established. The ubuntu leg wraps every run in `xvfb-run`, because that runner provides no display server for Electron's window. The acceptance run there also gets an unlocked gnome-keyring inside a dbus session, because the vault refuses account connects when `safeStorage` reports no operating-system encryption. Playwright's Electron loader forces `password-store=basic`, which discards that keyring, so a `RECOMPOSE_PASSWORD_STORE` environment seam mirrors the user-data seam and restores the platform backend under test. Like the user-data seam, it redirects a choice and grants no privilege.
- **A `RECOMPOSE_USER_DATA_DIR` environment variable gives every scenario a throwaway user-data directory.** `resolveUserDataOverride` reads that variable and, when it names a directory, the main process calls `app.setPath('userData', ...)` with it before Electron's `app.ready` event fires. Each launched instance then writes settings, accounts, and vault data into a fresh temporary directory instead of the developer's real one. The seam only redirects a path. It grants no privilege, since an attacker who already controls the process environment already controls the process itself.
- **A packaged-artifact smoke spec closes issue #58 by spawning the shipped binary directly and connecting over the Chrome DevTools Protocol (CDP).** The spec launches the packaged executable with `--remote-debugging-port=0`, reads the port it reports, and calls `chromium.connectOverCDP` against that port. Playwright's own `electron.launch` inspector handshake needs the `EnableNodeCliInspectArguments` fuse, and shipped binaries carry that fuse off per ADR-0028. Nothing in this suite relaxes a shipped fuse to make the smoke pass. The smoke exists to prove the artifact users run, not a weakened stand-in. Shipped fuses also block the usual main-process introspection, `app.isPackaged` and `getAppPath()` among them, so the spec can't ask the process directly whether it loaded from an archive. A successful boot to `app://renderer` stands in as the structural proof instead, since the `OnlyLoadAppFromAsar` fuse guarantees that only an asar-packaged origin can serve that page. Two further probes exercise the fuses directly. One spawns the binary with `ELECTRON_RUN_AS_NODE` set and polls a bounded window confirming the process never exits the way a plain Node interpreter would. The other spawns it with `--inspect=0` and confirms its `stderr` never carries a debugger-listening banner. On the Linux continuous-integration leg the two full-window launches also pass `--no-sandbox`, because the GitHub runner ships no configured setuid sandbox helper and Chromium's sandbox setup otherwise stalls the browser process before it binds the DevTools port. Playwright already makes the same accommodation for every source-mode launch through its Electron loader. The switch relaxes no shipped fuse, and the migrated boot proof still asserts the renderer's `sandbox` web preference directly.
- **`security-boot-proof.mjs` migrated into the runner as `boot-proof.spec.ts`, with its assertion scope unchanged.** One runner now owns reporting and traces for both the source-mode proof and the packaged smoke, and the bespoke script disappears. Two verified adjustments came out of the migration. The bridge-null check now reads `Object.is(globalThis.recompose, null)` instead of a plain truthy check. A truthy check would pass even if the runtime bridge arrived as `null`, because the ambient type declares `RecomposeIpc`, never `RecomposeIpc | null`. A looser assertion would typecheck away the exact failure it exists to catch. The navigation-guard assertion now polls `page.url()` through `expect.poll` instead of calling `toHaveURL`. A cancelled `will-navigate` produces an errored navigation event that `toHaveURL`'s internal waiter throws on. Tracing `playwright-core`'s own source located the race in an Electron-and-CDP interaction inside that waiter. Polling the URL directly sidesteps that waiter.
- **fuite and memlab both failed the memory-leak rider's one requirement: launching the actual Electron binary.** Both tools drive only a puppeteer-launched Chrome, and neither one launches an Electron application. A `@leak`-tagged spec fills that gap instead. It opens a CDP session against the page and warms up with five round trips between the home screen and the providers screen. It then forces garbage collection through `HeapProfiler.collectGarbage`, reads `Runtime.getHeapUsage` for a baseline, and runs twenty more measured round trips. The spec asserts the resulting heap stays under one and a half times that baseline. It runs on the ubuntu matrix leg only: V8's heap behavior doesn't vary by platform, so one leg keeps the flake surface small without losing coverage.
- **A flaky-test quarantine policy governs the whole suite.** This record states it here in full. A flaking test gets the `@quarantine` tag and a GitHub issue naming an owner and a two-week fix-or-remove deadline. A test leaves quarantine after twenty consecutive passing quarantine runs, or the team deletes it instead. No third-party flake-tracking service takes on this job. A separate `e2e-quarantine` job on ubuntu runs only tests carrying that tag, through `continue-on-error` and `--pass-with-no-tests`. The main `e2e` job excludes the tag through `--grep-invert @quarantine`. The quarantine lane never joins the `ci-success` needs list, so a still-flaking test never blocks the queue. Packaged-smoke tests stay in the required job because the quarantine lane builds no artifact.
- **Several riders landed alongside the runner.** The `check` job now caches the Playwright browser download at `~/.cache/ms-playwright` and keys the cache on the pnpm lockfile's hash. The vendored `playwright-best-practices` skill (currents.dev, `MIT` license) and the authored `gherkin-best-practices` skill both became mandatory for end-to-end work through a new CLAUDE.md rule. `@playwright/mcp` pins exact as a root devDependency and launches through `pnpm exec` at project scope. A gitleaks allowlist scopes the `generic-api-key` rule to only the `.agents/skills/` path, because vendored documentation there carries example tokens the scanner would otherwise flag. The owner-alias rule keeps scanning that same path in full. oxlint's blanket ignore for `apps/desktop/e2e/**` came off, so linting now covers every e2e source file. Generated `.features-gen/` output stays the only remaining exclusion. One file-scoped override turns off `no-empty-pattern` for `e2e/fixtures.ts`, because Playwright's fixture contract requires the literal empty `{}` destructuring pattern. ADR-0029 already set the same file-scoped override mechanism for the Storybook bridge decorator, though that override covers different rules.

## Alternatives

- **The Cucumber runner**: rejected. It drops Playwright's own fixtures, traces, and parallel workers, the exact machinery the acceptance suite depends on.
- **A macOS-only matrix**, the shape an earlier rider assumed: rejected once the maintainer confirmed the app ships to macOS, Windows, and Linux.
- **fuite and memlab for the memory-leak rider**: rejected. Neither tool launches an Electron binary, since both drive only a puppeteer-launched Chrome.
- **Relaxing a shipped fuse for the packaged smoke**: rejected. The smoke exists to prove the artifact users run, and a relaxed fuse would prove something else.
- **A third-party flaky-test tracking service**: rejected in favor of the in-repo tag-and-issue policy, which needs no new external dependency.
- **Keeping `security-boot-proof.mjs` as a standalone script**: rejected. Migrating it into the runner gives it the same reporting and trace capture every other spec already gets.
- **A blanket oxlint ignore for the whole `apps/desktop/e2e/**` directory**: rejected. Only the generated `.features-gen/` output needs the exclusion, and the rest of the directory benefits from the same lint coverage as every other source file.

## Consequences

**Good**: every scenario runs against the real Electron binary, in source mode and packaged mode alike, on every platform the app ships to. The `.feature` files stay a readable approval artifact the maintainer can review without reading a line of automation code. Issue #58 closes with a packaged smoke that proves the asar-loaded, fused artifact users receive. The migrated boot proof keeps the exact security assertions ADR-0028 established, now inside a runner that reports traces on failure. The quarantine lane gives a flaking test a governed, time-boxed path instead of a silent skip or a blocked queue.

**Bad, and accepted**: Windows and Linux runners are new territory for this app's Electron tests, so first-run flakes are plausible until the suite settles. The packaged smoke can't verify `app.isPackaged` or `getAppPath()` directly, since shipped fuses block that introspection. It leans on the `app://renderer` boot and the `OnlyLoadAppFromAsar` fuse as indirect proof instead. The heap-growth bound, one and a half times baseline, is an empirical threshold, not a hard guarantee against every leak shape. A future maintainer widening it needs a documented reason, the same discipline ADR-0021's complexity ceiling already set. The packaged smoke depends on the shipped binary honoring the `--remote-debugging-port` switch, so a future hardening pass that filters command-line switches must revisit the smoke's transport.
